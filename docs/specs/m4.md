## 0. Current data flow (what M4 changes)

```
HomeView "Capture forward pass"
  └─ POST /api/runs {model, weights, sample}  ──▶ RunManager.create_from_spec   (synchronous, whole request)
        load_model → build_input → _create (under _lock): capture() → tensors/*.npy until
        NEUROTOME_MAX_CAPTURE_MB is crossed (every later op: saved=false, stats=null) → meta.json, ir.json
  ◀─ run meta → navigate(#/runs/<id>/graph)
Errors: ValueError/KeyError/ImportError/AttributeError → 400; anything else → bare 500.
```

Verified on this machine while writing the spec (torch 2.14, torchlens 2.34.1, captum 0.9.0):

| Model | Capture | Attribution today |
|---|---|---|
| forward returns `SimpleNamespace(score=…)` or `"hello"` | succeeds, `meta.output == []` | `TypeError: Cannot find a tensor in model output of type SimpleNamespace` → 500 |
| `nn.Embedding` on `torch.randint` input | succeeds | node scores work, `input` silently `null`; layer IG: `RuntimeError: only Tensors of floating point dtype can require gradients` |

| `py:` spec whose module is gone | — | `ModuleNotFoundError` from `live()` → 500 |

## 1. Backend (package A)

### 1.1 `errors.py` (new): one place that turns exceptions into user-facing messages

```python
class TraceError(ValueError):
    """TorchLens could not trace forward(). HTTP 422."""

class ModelUnavailable(RuntimeError):
    """A run's model is not loaded and cannot be reloaded. HTTP 409."""

NO_GRAD = ("The objective has no gradient: forward() leaves autograd between the input and the output "
           "(for example .numpy(), .item(), .detach() or torch.no_grad()), so gradient methods cannot run on "
           "this model. The graph and tensors are still valid.")

def describe(e: BaseException) -> tuple[int, str]:
    """(HTTP status, message) for any exception; the message never contains a traceback."""
    # torch.cuda.OutOfMemoryError → 413, oom_message(e)
    # TraceError                  → 422, str(e)
    # ModelUnavailable            → 409, str(e)
    # ValueError                  → 400, str(e)
    # RuntimeError whose text contains "does not require grad" → 400, NO_GRAD   (ponytail: message sniffing)
    # anything else               → 500, f"{type(e).__name__}: {e}"
    # an empty message is replaced by the exception type name

def oom_message(e) -> str:
    # f"CUDA ran out of memory ({first line of str(e)}). Capture on the CPU instead (neurotome serve --device cpu "
    # "or NEUROTOME_DEVICE=cpu), lower the capture budget, or capture fewer modules."
```

`KeyError` is **not** mapped globally; the API keeps its local 404 handling (`_meta`, `_tensor`, `_job`).

### 1.2 `capture.py`

```python
def capture(model, inputs, store, run_id, max_bytes: int | None = None, modules: list[str] | None = None,
            progress: Progress | None = None) -> dict
```

- **Trace failures.** Wrap `_run_trace` in `try`. Re-raise `torch.cuda.OutOfMemoryError` unchanged; wrap any other
  exception as `TraceError(f"TorchLens could not trace forward(): {type(e).__name__}: {first line, ≤ 300 chars}. "
  "Check that model(x) runs on this input outside Neurotome; ops TorchLens cannot record (custom CUDA kernels, "
  "C++ extensions) are the usual cause.") from e`.
- **Progress.** `progress(0.12, "Trace")` before the trace. After it, with `N = len(ops)`:
  `progress(0.2 + 0.7 * i / N, f"Save tensors {i}/{N}")` every `max(1, N // 50)` ops and after the last one.
  `progress` may raise `jobs.Cancelled`; let it propagate (the caller deletes the run folder).
- **Selective capture.** `modules` is a list of module addresses (`"layer3"`, `"layer4.1.conv2"`), or `None` for
  every op. Right after the trace, validate them against the traced module addresses (the keys of the IR
  `modules` table, root excluded); unknown ones raise
  `ValueError(f"Unknown module(s) {', '.join(bad)}; pick addresses from the module tree, e.g. {first 5 depth-1 addresses}")`
  before anything is saved. An op is *inside* when any call in its module stack, with the `:<call>` suffix
  stripped, is in the selection (the stack lists ancestors, so `layer3` covers everything under it). TorchLens
  still traces with `layers_to_save="all"`; only what reaches disk changes
  (`# ponytail: memory during the trace is unchanged; pass TorchLens layer labels when big models need it`).
- **Budget.** Replace the "save until crossed" rule with "never cross": for each op in order,
  `need = out.numel() * 4` (float32 on disk). Input and output ops are always saved. Otherwise the op is skipped
  with `unsaved = "modules"` when it is outside the selection (it does not consume budget), else with
  `unsaved = "budget"` once `total + need > max_bytes` has happened for any earlier-or-this op (a prefix rule:
  after the first op that does not fit, every later non-io op is skipped for the budget).
- **Stats for every op with a tensor**, saved or not (one CPU copy, then dropped), so colour modes and the
  inspector histogram work on unsaved nodes. Ops without a tensor keep `stats: null`.
- IR changes (all new fields optional for readers; old runs lack them):

```jsonc
"model": { /* existing */ "truncated": true,          // now: at least one op has unsaved == "budget"
           "budget_bytes": 2147483648 | null,          // the budget this capture used
           "capture_modules": ["layer3", "layer4"] | null,
           "saved_ops": 412 },                          // non-io ops with saved == true (compare with num_ops)
"ops": [{ /* existing */ "saved": false,
          "unsaved": null | "budget" | "modules" | "no_tensor" }]   // null iff saved
```

- **No-gradient check** in `op_gradients`: before `trace.log_backward(root)`, `if not root.requires_grad: raise
  ValueError(errors.NO_GRAD)`.

### 1.3 `models.py`: `to_logits`

- Keep the order: tensor → `.logits` (only when not `None`) → dict → tuple/list. Search dict/tuple/list values
  with a default (`next(..., None)`); never let `StopIteration` escape.
- No tensor found → `ValueError(f"The model returned {type(output).__name__}, which holds no tensor. Neurotome "
  "explains a tensor output: return logits, a dict/tuple/list that holds a tensor (the first one is used), or an "
  "object with .logits (Hugging Face ModelOutput).")`.
- An integer or bool tensor → `ValueError(f"The model output is {out.dtype}; attribution needs float logits.")`.
- A 0-d tensor becomes `(1, 1)`; the existing 1-d / 3-d / >2-d rules stay.

### 1.4 `attribution.py`

- `attribute()` result gains `"input_note": str | None`. It is `None` when an input map was computed. When the
  input is not a float tensor, `input` stays `None` and
  `input_note = f"{METHODS[method]} needs a float input; this input is {x.dtype} (token ids?), so input attribution is skipped. Node scores (gradient × activation) still cover every op; embedding-layer methods are planned for v0.2."`
  (for a non-tensor input: `"Input attribution needs a tensor input; node scores still cover every op."`).
  Cached results without the key read as `None`.

### 1.5 `runs.py`

```python
def create_from_spec(self, spec, weights, sample, modules=None, max_capture_mb=None, progress=None) -> dict
def create_from_objects(self, model, inputs, name=None, categories=None, modules=None, max_capture_mb=None,
                        progress=None) -> dict
def start_capture(self, spec, weights, sample, modules=None, max_capture_mb=None) -> Job
```

- `create_from_spec` reports `progress(0.02, "Load model")`, then `progress(0.08, "Build input")`, and passes
  `progress` into `_create` → `capture`; `_create` reports `progress(0.93, "Summarise")` before the preview, top-k
  and JSON writes. `progress=None` is the synchronous path the CLI and `neurotome.open()` keep using.
- `_create`'s existing `except Exception: store.delete(run_id); raise` also covers `Cancelled` and OOM; after
  an OOM it also calls `_free_cuda()`.
- Load failures: `ImportError`, `AttributeError`, `KeyError`, `TypeError` from `load_model` in
  `create_from_spec` become `ValueError(f"Cannot load model {spec!r}: {type(e).__name__}: {e}")`.
- `modules`: strip, drop empties, `None` when nothing is left. `max_capture_mb` (> 0) overrides
  `self.max_capture_bytes` for this capture only (`int(mb * 1024 * 1024)`).
- `start_capture` validates cheap things **before** queueing (→ `ValueError`, HTTP 400): the spec prefix is
  `torchvision:` or `py:` (the same text as `load_model`'s error); an upload sample's file exists in `_uploads`
  (`"Upload {id} not found; upload the file again"`). Then
  `self.jobs.submit("capture", lambda p: self.create_from_spec(..., progress=p))` with `run_id=None`, `key=None`.
  The job's `result` is the run meta.
- `_top_k` returns `(top, error)`; meta gains `"output_error": str | None`, the `describe()` message of the failure
  (e.g. the `to_logits` ValueError above), `None` when top-k worked.
- `live()`:
  - not reloadable → `ModelUnavailable("This run was created in-process (neurotome.open) and its model is no
    longer loaded. Run neurotome.open(model, x) again to attribute it; the graph and tensors stay browsable.")`;
  - `load_model` raising anything but `torch.cuda.OutOfMemoryError` →
    `ModelUnavailable(f"The model of {run_id} ({spec}) can no longer be loaded: {type(e).__name__}: {e}. py: specs import from the server's working directory; start neurotome from the folder that holds the module, or capture a new run.")`.
- Integer inputs: `layer()` and `neuron()` raise, before any work,
  `ValueError(f"Layer methods interpolate the input from a zero baseline and need a float input; this run's input is {dtype}. Embedding-layer methods are planned for v0.2.")`
  when `_first(live.inputs)` is not a floating tensor (agreement then lists this in `units_error`, as for any
  failing method).
- `.npy` uploads keep integer arrays as `int64` (`np.issubdtype(a.dtype, np.integer)`); everything else becomes
  float32 as today.
- `RunManager.__init__`: `self.jobs = JobRunner(describe=lambda e: describe(e)[1])`.

export type Theme = "light" | "dark";
export const THEME_KEY = "neurotome.theme";
export function resolveTheme(stored: string | null, systemDark: boolean): Theme;   // stored "light"/"dark" wins, else system
/** What to store after choosing `next`: null (follow the system again) when it equals the system theme. */
export function storedFor(next: Theme, system: Theme): Theme | null;
export function parseColor(s: string): [number, number, number];   // "#rgb", "#rrggbb", "rgb(r, g, b)", "rgba(…)"
export function contrast(a: string, b: string): number;             // WCAG 2 ratio
export type Tokens = Record<"paper" | "panel" | "ink" | "ink2" | "line" | "lineFaint" | "accent" | "accentSoft" | "negative" | "fontMono", string>;
export function readTokens(): Tokens;     // colours resolved through a hidden probe (`forced-color-adjust: none`),

export function useTheme(): [Theme, () => void];   // toggle: applies data-theme, stores storedFor(...) (try/catch),

export function useTokens(): Tokens;      // re-read on every theme change (a "neurotome:theme" window event and
