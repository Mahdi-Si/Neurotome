# M1 · Graph workspace: implementation spec

Status: ready to build · Covers PLAN.md §7 M1 (all seven items) · Read with ARCHITECTURE.md and DESIGN.md.

This is the first milestone spec. Later milestones follow the same shape (see §10).

## 0. Current data flow (what M1 changes)

```
ir.json ──graph_view(ir, depth, scores)──▶ GET /graph ──▶ GraphView.tsx ──▶ GraphCanvas.tsx
  ops[].stats (capture.tensor_stats)          nodes/edges/groups     useAsync      layoutGraph (ELK, main thread)
                                                                                   every node = <button>, every edge = <path>
```

M1 adds per-module fold overrides, a search index endpoint, NaN/Inf counts, dtype/device on nodes and
edges, an ELK Web Worker with a layout cache, a canvas edge layer with node virtualisation, a minimap,
search, keyboard navigation and colour modes. Nothing reads TorchLens outside `capture.py`, and the
browser still gets only summaries.

Compatibility rule (applies throughout): **runs captured before M1 must still open.** Every new IR field is
read with `.get(...)` and becomes `null` in the API. The frontend treats a missing value as "not recorded".

## 1. Backend

### 1.1 IR changes (`capture.py`)

Per op, add:

| Field | Type | Source |
|---|---|---|
| `device` | `str \| null` | `str(out.device)` of the first output tensor (TorchLens keeps activations on the original device, since `output_device="same"`), or `null` when there is no tensor output |

The `dtype` field is already recorded, for example `"torch.float32"`. Keep it as it is.

In `stats` (`tensor_stats`), add:

| Field | Type | Meaning |
|---|---|---|
| `nan` | `int` | `np.isnan(flat).sum()` |
| `inf` | `int` | `np.isinf(flat).sum()` |

Both fields are present in both branches of `tensor_stats`, including the all-non-finite branch. No L2 field
is needed, because the frontend derives RMS exactly from the existing fields: `rms = sqrt(mean² + std²)`, where
`std` is the population std over finite values. That formula also works for old runs.

Update the IR schema docstring at the top of `capture.py`.

### 1.2 Graph view with per-module overrides (`graph.py`)

New signature (the positional order stays compatible):

```python
def graph_view(ir, depth=2, scores=None, expand=(), collapse=()) -> dict
```

`expand` and `collapse` are iterables of **module calls** (`"layer1.0:1"`). Unknown calls are ignored.
Define `collapsed(call, i) = call in collapse or (i >= depth and call not in expand)`, where `i` is the call's
index in the op's module stack. **`collapse` wins over `expand`.**

Folding rule, which replaces step 1 in ARCHITECTURE.md. For each op with stack `S` (empty for input/output):

- `i* = min{ i : collapsed(S[i], i) and len(ops_in_call[S[i]]) > 1 }`
- if `i*` exists: node `m:S[i*]`, containers `S[:i*]`
- else: op node, containers `[c for c in S if len(ops_in_call[c]) > 1]`

With empty overrides this gives the same output as today. The existing depth tests must pass unchanged.
Groups, representative ops and edges keep their current algorithm.

Also replace `order.index(...)` in the group sort with a precomputed `{op_id: position}` dict. It is
O(n²) on big graphs.

Node additions. Every node gets:

| Field | Type | Value |
|---|---|---|
| `dtype` | `str \| null` | representative (`output_op`) op's `dtype` (empty string → `null`) |
| `device` | `str \| null` | representative op's `device` (`null` on old runs) |
| `nonfinite` | `int \| null` | Σ over **all member ops** of `stats.nan + stats.inf`; `null` when no member has these keys (old run, or nothing saved) |

Edge additions. An edge's metadata comes from the first `(parent p → op oid)` pair in IR order that
creates it; that pair already provides `shape`:

| Field | Value |
|---|---|
| `dtype`, `device` | parent op `p` (the tensor the edge carries) |
| `target_dtype`, `target_device` | consuming op `oid` (its output) |

All four are `str | null`.

### 1.3 Search index (`graph.py`)

```python
def search_index(ir) -> list[dict]
```

The index has one entry per op (IR order) and then one per **module call with more than one op**
(first-use order). Single-op calls never become nodes, so they are skipped.

```jsonc
{"id": "conv2d_3_8",   "kind": "op",     "label": "conv2", "path": "layer1.0.conv2", "type": "conv2d",
 "shape": [1,64,56,56], "calls": ["layer1:1", "layer1.0:1", "layer1.0.conv2:1"]}   // op: its full module stack ([] for input/output)
{"id": "m:layer1.0:1", "kind": "module", "label": "0",     "path": "layer1.0",       "type": "BasicBlock",
 "shape": [1,64,56,56], "calls": ["layer1:1"]}                                        // module: ancestor calls only
```

- An op entry's `label`, `path` and `type` are computed exactly as for an op node in `graph_view`. Factor
  that code into one private helper so both callers share it.
- A module entry's `shape` is the shape of the last op in the call. Its `type` is `class_name`, and its
  `calls` are the calls before it in any member op's stack.
- Add a `# ponytail:` note: the full index is sent to the client. Above about 20k ops, switch to server-side
  `?q=` filtering.

### 1.4 HTTP API (`api.py`)

| Method | Path | Change |
|---|---|---|
| GET | `/api/runs/{id}/graph?depth=2&expand=a,b&collapse=c[&method=&target=&steps=]` | new optional `expand` and `collapse` query params, each a **comma-separated** list of module calls (default `""`); split on `,` and drop empty items; passed to `graph_view` |
| GET | `/api/runs/{id}/index` | **new**. Returns `search_index(ir)` as a JSON list; 404 for an unknown run |

All other routes are unchanged. Example response node (additions marked `+`):

### 1.5 Backend tests (`backend/tests/test_graph_m1.py`, new; reuse `Tiny` by importing from `test_pipeline`)

1. `expand`: at `depth=0`, `graph_view(ir, 0, expand=["block:1"])` has no `m:block:1` node. It has a
   `g:block:1` group, or else nodes whose `group` is inside block, and it has more nodes than depth 0.
2. `collapse`: at `depth=3`, `collapse=["block:1"]` gives an `m:block:1` node and no `g:block:1` group. When
   the same call is in both lists, collapse wins.
3. With no overrides, the output is identical to `graph_view(ir, d)` for d in 0..3 (a regression guard). Unknown calls are ignored.
4. `tensor_stats` counts NaN and Inf: an array with 2 NaN and 1 Inf gives `nan == 2` and `inf == 1`, and an
   all-NaN array still has both keys.
5. Node `nonfinite`: put a NaN into one op's stats in an IR copy. The module node that contains it reports
   `nonfinite >= 1`. With `nan`/`inf` keys removed from every stats (an old run), `nonfinite is None`.
6. dtype/device: every node and edge of a captured Tiny run has `dtype == "torch.float32"` and `device == "cpu"`.
   An IR copy without `device` keys still builds and gives `device is None`. On CUDA (skip when
   unavailable), the device starts with `"cuda"`.
7. `search_index`: contains every op id plus `m:block:1` with `calls == []`; the entry for `block.conv1`'s
   op has `calls` ending with `"block.conv1:1"`.
8. HTTP: `GET /graph?depth=0&expand=block:1` differs from `depth=0`; `GET /index` returns 200 and a list;
   `GET /index` on `run_9999` returns 404.

Checks: `cd backend && ../.venv/Scripts/python.exe -m pytest -q && ../.venv/Scripts/python.exe -m ruff check .`

Package B lands these edits **first**, in the exact shape below. Package C codes against them.

// types.ts: additions

## 3. Item 1: per-module expand/collapse

**Behaviour**
- A module node shows a 16×16 `+` toggle in its top-right corner. A group box shows a `−` toggle to the
  left of its header label. Clicking a toggle calls `onToggle(call, open)` and does **not** change the
  selection.
- Keyboard: `+` or `=` on a selected module node expands it. `-` collapses the selected node's innermost
  group (`node.group`).
- The toggle is a separate `<button>` placed over the card, a sibling rather than a child of the node
  button, because a button inside a button is invalid HTML. Style: mono 11px, 1px ink border, panel
  background, `aria-label="Expand layer1.0"` or `"Collapse layer1.0"`.
- Fold state is in the URL hash: `#/runs/<id>/graph?depth=1&expand=layer1.0:1,layer2:1&collapse=…&node=…&color=…`.
  Calls are comma-joined, and `URLSearchParams` encodes `:`.
- Clicking a depth button resets `expand` and `collapse` to empty.
- **Viewport anchoring** (package B): when a toggle fires, GraphCanvas records the toggled element's screen
  position. After the next layout it moves the view so the counterpart element sits at the same screen
  position (`m:call` ↔ `g:call`), so the graph does not jump. The view refits only on first placement or
  when `view.depth` changes; other re-layouts keep `tf`.

**Pure logic** (`lib/graphState.ts`, package C):

```ts
parseFold(params: URLSearchParams): Fold
foldParams(f: Fold): { expand: string | null; collapse: string | null }   // null when empty, for href()
toggleFold(f: Fold, call: string, open: boolean): Fold
  // open:  expand ∪ {call}, collapse − {call}
  // close: collapse ∪ {call}, expand − {call}
revealFold(f: Fold, entry: IndexEntry): Fold   // expand ∪ entry.calls, collapse − entry.calls
```

**Tests**: vitest cases for `toggleFold` (open then close gives collapse-only, no duplicates), a
`parseFold`/`foldParams` round-trip, and `revealFold` (removes the calls from collapse). Backend tests 1.5 #1–3.

## 4. Item 2: ELK in a Web Worker plus a layout cache (`lib/layout.ts`, package B)

- `getElk()`: when `typeof Worker !== "undefined"`, use
  `import ElkApi from "elkjs/lib/elk-api.js"` and `import workerUrl from "elkjs/lib/elk-worker.min.js?url"`,
  then `new ElkApi({ workerUrl })`. That is a classic worker, and the file is emitted as an asset into
  `static/assets`. Otherwise, and if constructing the worker throws, fall back to today's dynamic import of
  `elk.bundled.js`. That fallback is the path vitest in Node uses. Load both lazily, so the home page stays light.
- Cache: `layoutKey(view)` is a string built from the sorted node ids with each node's group, the group ids
  with their parents, and the edges as `s>t`. It is derived from content, so it covers
  (run, depth, expansion state). Attribution and colour changes do not change it, and neither do pan or zoom.
  `layoutGraph(view)` returns the cached `Placed` on a hit. Keep a `Map` bounded to 24 entries, dropping the
  oldest first. Store the promise so concurrent calls share one layout.
- `PlacedEdge` gains `bbox: Box` (the polyline's bounding box) for culling and hit testing.
- GraphCanvas never re-lays out on pan or zoom. The layout effect depends only on `view`.

**Tests** (`lib/perf.test.ts`): a second `layoutGraph` call with a *new* view object of the same structure
returns the same `Placed` object (`toBe`) in under 20 ms.

## 5. Item 3: minimap and search

### Minimap (`components/Minimap.tsx`, package B, rendered inside GraphCanvas)
- It sits bottom-left of the canvas (`left:16; bottom:16`), 200 px wide, with height set by the graph's
  aspect ratio (at most 140 px). It has a `panel` background and a 1px `var(--line)` border.
- It is one `<canvas>`. Groups are 1px `line-faint` strokes and nodes are filled `ink` at 0.55 alpha, or
  with the tone colour when tones are set. The selected node is filled with `accent`. The canvas redraws
  only when `placed`, `tones` or `selected` changes.
- The viewport rectangle is an absolutely positioned div with a 1px `accent` border, updated from `tf`.
- Pointer down or drag on the minimap centres the main view on that graph point, using pointer capture.
- It is hidden when the graph fits entirely in the viewport.

### Search (`components/GraphSearch.tsx`, package C, rendered by GraphView)
- It sits top-left of the graph section at `left:16; top:52`, under the "Forward trace" labels, and is
  280 px wide. It is a `.field`-styled input with `IconSearch` and the placeholder
  `Search name, type or shape  /`.
- `/` or Ctrl/Cmd+K focuses it when focus is not already in an input.
- Data: `api.index(run.id)`, loaded once per run with `useAsync`.
- Matching (`searchIndex` in `lib/graphState.ts`):
  - The query is lowercased and split on whitespace. Every token must be a substring of
    `label`, `path`, `type` or `shapeShort(shape)`.
  - A token that matches `/^\d+([x×,]\d+)+$/` is normalised to `×` separators first, so
    `64x56x56` finds `64×56×56`.
  - Ranking: exact label match (0) < label prefix (1) < anything else (2). Ties go to modules before ops,
    then index order. At most 8 results; an empty query gives no results.
- Results render as a list under the input. Each row shows mono `label`, dim `type`, `shapeShort` on the
  right, and the `path` as a dim second line. ↑/↓ move the active row, which gets the `accent-soft` fill.
  Enter or a click selects the row. Escape clears the query and blurs the input.
- Selecting an entry sets the URL in one `navigate(…, true)`. The fold becomes `revealFold(fold, entry)`
  and the node becomes `entry.id`, which reveals a node folded inside collapsed modules. GraphView then
  increments `centre`.
- Resolving the selection after the reveal:
  1. `view.nodes` by id
  2. then by `output_op`
  3. then, for an `m:` id, `pickNodeForModule(view, path)` (existing)
  4. then the current fallback

**Tests**: `searchIndex` finds a module by name and orders it before ops that only match on path, finds
by op type, finds by `64x56x56`, ANDs multiple tokens, and caps at 8 results. The minimap needs no unit
test; its maths lives in `viewport.ts` (see §9).

## 6. Item 4: keyboard navigation (package B in GraphCanvas; package C wires callbacks)

- The canvas wrapper is the **single tab stop**: `tabIndex=0`, `role="application"`,
  `aria-label="Computation graph. Arrow keys follow edges, Enter opens tensor"`. Node buttons get
  `tabIndex=-1`.
- The focus state is `.graph-canvas:focus-visible { outline: 1.5px solid var(--accent); outline-offset: -2px }`
  in `global.css`. The selected node keeps its accent border.
- Keys, handled only when the canvas has focus, and each calls `preventDefault`:

| Key | Action |
|---|---|
| ↓ | child, the edge target of `selected`, whose centre x is nearest to the current node's |
| ↑ | parent, the edge source nearest in x |
| ← / → | nearest sibling strictly left or right of the current x; siblings are the other children of the current node's parents plus the other parents of its children |
| Enter | `onOpen(selected)` |
| Escape | `onEscape()` |
| + / = , − | see §3 |

  With nothing selected, any arrow selects the input node, or else the first node.
- Pure: `step(view, placed, current: string | null, key): string | null` in `lib/viewport.ts`. It returns
  `null` for no move.
- C wiring:
  - `onOpen(id)` navigates to `href(run.id, "tensors", { node: <node>.output_op })`. Use `output_op` because
    module ids do not exist in the Tensors view.
  - `onEscape` clears the search query. The query is lifted into GraphView state and passed to
    GraphSearch as `query`/`onQuery`.
  - Fix the Inspector's "Open tensor" link to use `output_op` in the same way.
- TraceView (C) passes `onOpen` too.

**Tests** (`lib/viewport.test.ts`): a diamond graph `in→a, in→b, a→out, b→out` with a hand-made `Placed`
(a left of b). Down from `in` goes to `a`. Right from `a` goes to `b`. Up from `out` goes to the nearer
parent. Left from `a` returns `null`. With `null` current, it selects the input.

## 7. Item 5: node colour modes

**URL**: `color=plain|attr|norm|sparsity|nan`, defaulting to `plain`. The legacy `overlay=attr` maps to
`attr`. Only `attr` triggers a refetch (`api.graph(..., {method:"gxa"}, fold)`, as today). The other modes
use `node.stats` and `node.nonfinite`, which every graph response already carries.

**UI**: in the TopBar, `Colour` and a `.seg` with `Plain · Attr · Norm · Sparsity · NaN/Inf` replace
today's Plain/Attribution pair. The legend panel stays top-right of the canvas, where it is today.

**Pure** (`lib/graphState.ts`, package C):

```ts
colorMode(params: URLSearchParams): ColorMode
nodeTones(view: GraphView, mode: ColorMode): {
  tones?: Map<string, NodeTone>;
  legend: { title: string; lo: string; hi: string; note?: string } | null;
}
```

| Mode | `v` (0..1) | `flag` | `readout` | Legend |
|---|---|---|---|---|
| plain | — (no `tones`) | — | — | none |
| attr | `score_norm` | — | `\|g×a\| ${num(score,3)}` | title `Node = \|grad × act\| · gxa · target top`, `0` … `max` |
| norm | `rms / max(rms over view)`, where `rms = sqrt(mean² + std²)` | — | `RMS ${num(rms)}` | `RMS = ‖x‖₂/√n (finite values)`, `0` … `num(max)` |
| sparsity | `zero_frac` (absolute scale) | — | `Zero ${pct}` | `Zero fraction`, `0%` … `100%` |
| nan | `null` | `nonfinite > 0` or (`stats.numel > 0` and `stats.mean === null`) | `NaN/Inf ${nonfinite ?? "—"}` | `Flag = NaN / Inf present`, `hi` = `${k} flagged`; `note: "Not recorded for this run · re-capture to check"` when no node has `nonfinite != null` and none is flagged |

Nodes with no data get `v: null` and are drawn plain. Module nodes use their representative output, and
the legend says `Module = its output tensor` as a second dim line in scalar modes.

**Drawing** (package B, in GraphCanvas and Minimap):
- The fill is `mix(panel, accent, 0.08 + 0.32·v)`, capped at 40 % accent so ink text keeps at least
  7:1 contrast. The 3 px accent bottom bar has width `v`, as in today's attribution bar.
- `flag`: 1.5px `var(--negative)` border plus a mono `NAN/INF` badge in `negative-text` in place of the
  shape text. This is the only use of the negative colour.
- `readout` is appended to the node `title` and shown in the hover readout (§8).
- `mix(a,b,t)` lerps hex colours in `viewport.ts`. Token hex values are read once via
  `getComputedStyle(document.documentElement)`, so canvas and DOM agree.

**Tests** (C): for `nodeTones`:
- attr passes `score_norm` through;
- norm puts `v = 1` on the max-RMS node and derives RMS from mean and std;
- sparsity equals `zero_frac`;
- nan flags `nonfinite > 0` and an all-non-finite stats;
- a view whose nodes lack `nonfinite` gives the note.

## 8. Item 6: edge hover readout (package B)

- Hit testing: on pointer move (throttled to one call per animation frame), convert to graph coordinates
  and call `hitEdge(placed, gx, gy, 5 / k)`. It returns the index of the nearest in-view edge polyline
  within tolerance, checking each edge's `bbox` inflated by the tolerance first. A node box under the
  pointer takes precedence and clears the edge hover.
- The hovered edge is redrawn on the canvas in `accent` at 1.5px.
- The readout line is mono `.lbl` and `pointer-events:none`. It sits at the bottom of the canvas, left of
  the zoom controls and right of the minimap (`left:232; bottom:22`). It follows DESIGN's hover-readout rule.
  - Edge: `conv1 → bn1 · 64×56×56 · float32 · cpu`.
  - When `target_dtype` or `target_device` differs from `dtype`/`device`: `float32 → float16 · cuda:0 → cpu`,
    with the changed part in `accent`.
  - Missing fields (old runs) are omitted. The `torch.` prefix is stripped.
  - Node hover shows `displayName · type · shape` plus the tone readout.

**Tests** (`viewport.test.ts`): `hitEdge` finds a horizontal segment 3 px away, misses at 10 px, and picks
the nearer of two edges.

## 9. Item 7: performance budget (package B)

**Rendering model** (`GraphCanvas.tsx`):
1. **Edges and group rectangles** are drawn on one `<canvas>` sized to the viewport × `devicePixelRatio`
   (with a `ResizeObserver`). Each redraw, scheduled once per animation frame when `tf`, `placed`, `tones`,
   hover or selection change, applies `setTransform(dpr·k, 0, 0, dpr·k, dpr·x, dpr·y)`.
   - Only edges from `edgesInView` are drawn.
   - Plain mode: **one** `beginPath`/`stroke` for all edges (1px ink, scaled by 1/k), with chevron arrowheads
     in the same path.
   - Flow mode: edges are bucketed by rounded stroke width into one path per bucket, plus one accent path
     for `on_path`. Share labels at merges are drawn with `fillText` in the mono font.
   - Groups are dashed `setLineDash([3,3])` rects.
2. **Nodes** are HTML buttons (`React.memo` `NodeCard`), rendered only for `visibleNodes(placed, tf, W, H, 200)`,
   the boxes that intersect the viewport inflated by 200 screen px, and only while `k >= DOM_MIN_ZOOM` (0.4).
   Below 0.4, nodes are drawn on the canvas as filled rects with tone fill, selection and flag borders. A click
   (pointer up without a drag of more than 3 px) uses `hitNode` to select.
3. **Group headers** (label, counts and `−` toggle) are HTML, virtualised the same way, and shown only at `k >= 0.4`.
4. Pan and zoom change only the `tf` state, which drives the transform of the node layer and a canvas redraw.
   The layout never reruns (§4).

**Pure** (`lib/viewport.ts`, all O(n) scans with no index. `# ponytail:` a linear scan per frame is fine to
about 20k nodes; add a grid index if the benchmark says otherwise):

```ts
export interface Tf { x: number; y: number; k: number }
export const DOM_MIN_ZOOM = 0.4;
visibleNodes(placed: Placed, tf: Tf, w: number, h: number, margin?: number): string[]
edgesInView(placed: Placed, tf: Tf, w: number, h: number): number[]      // indices into placed.edges
hitNode(placed: Placed, gx: number, gy: number): string | null
hitEdge(placed: Placed, gx: number, gy: number, tol: number): number | null
step(view: GraphView, placed: Placed, current: string | null, key: string): string | null
mix(a: string, b: string, t: number): string                              // "#rrggbb"
toScreen / toGraph helpers as needed by the minimap
```

**Benchmark** (`lib/perf.test.ts`, which runs in `npm test`; give the file a 30 s timeout):
- `syntheticView(2000)`: 250 groups × 8 op nodes each in a chain, plus a residual edge from each block's
  input to its last node, and chain edges between blocks.
- `layoutGraph` (bundled ELK in Node) takes **< 6000 ms**; it was measured at about 0.9 s on the dev box.
- A cache hit takes < 20 ms and returns the same object (§4).
- Over 500 seeded random transforms (k ∈ [0.05, 2.5], a 1600×900 viewport), `visibleNodes + edgesInView`
  must average **< 1 ms** per frame.
- At k = 1 on 1600×900, `visibleNodes` returns ≤ 150 ids. At k = 0.4 it returns ≤ 400, which is the
  worst-case DOM node count.
- Log the measured numbers with `console.info`, so the benchmark doubles as a dev report.

## 10. Conventions for later milestones

- Specs go in `docs/specs/mN.md`, and work packages have disjoint file ownership. Shared contracts
  (`types.ts`, `api.ts`, `api.py`) have exactly one owner, and that owner lands the contract edits first.
- Frontend logic lives in pure functions in `lib/*.ts`, tested with vitest in the Node environment (no DOM).
  Components stay thin.
- New IR fields are optional. Readers use `.get()` or `?.`, and missing data shows as `—` or "not recorded".
- Fold ids are module calls (`name:N`). Node ids are `m:<call>` and group ids are `g:<call>`.
- URL hash params for graph state are `depth`, `expand`, `collapse`, `color` and `node`.
