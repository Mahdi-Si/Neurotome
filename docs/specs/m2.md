# M2 · Tensor inspector: implementation spec

Status: ready to build · Covers PLAN.md §7 M2 (six items) plus one M1 carry-over · Read with ARCHITECTURE.md,
DESIGN.md and `docs/specs/m1.md` (its §10 conventions still apply).

## 0. Current data flow (what M2 changes)

```
tensors/<op>.npy ──tensor_view(arr, channel, pixel)──▶ GET /ops/{op}/tensor?channel=&py=&px= ──▶ TensorView.tsx
   (memmap, float32)   maps: top-32 × 24×24, each _norm01            (py/px accepted, never sent)       ImageBody: grid, DotMatrix,
                       dots: selected channel 16×16, _norm01                                              LinePlot, DivergingBars
inputs.pt (not shown anywhere)                                                    TraceView: attr.input.map as DotMatrix only
```

M2 adds:
- pixel picking (URL `py`/`px`), with a crosshair;
- server-side `norm` (per channel or global) and `cmap` (sequential or diverging) scaling;
- an `input_preview.png` written at capture time, served by a new endpoint and drawn under channel and attribution maps;
- a slice grammar with a capped JSON table and a capped `.npy` download;
- a diff endpoint and a compare mode;
- PNG export on every chart;
- the ModuleTree fix.

Every new response stays bounded:
- the table sends at most 4096 values;
- `.npy` holds at most 2²⁴ values;
- diff sends statistics only;
- the preview is at most 224 px.

Compatibility rule from M1 still applies: runs captured before M2 must open. The only new run artifact is
`input_preview.png` and the only new meta field is `preview`. Both are optional, and their absence disables the overlay.

## 1. Backend (package A)

### 1.1 `tensors.py`: norm and colormap scaling, peak fix, preview, diff

New signature (positional order unchanged):

```python
def tensor_view(arr, channel=None, pixel=None, max_channels=32, map_size=24, dot_size=16,
                norm="channel", cmap="seq", lo=None, hi=None) -> dict
```

One scaler replaces `_norm01` in the image view. Keep `_signed`, because the sequence view uses it.

```python
def _scale(g, lo, hi, cmap):
    # seq: (g-lo)/(hi-lo) clipped to [0,1], zeros when hi <= lo
    # div: g/max(|lo|,|hi|) clipped to [-1,1], zeros when that is 0; 0 always maps to 0
    # np.nan_to_num on the result (Starlette's JSON encoder refuses NaN)
```

Image view behaviour:

| `norm` | range used for each of `maps[i]` and for `dots` |
|---|---|
| `channel` (default) | that pooled grid's own `[min, max]`, which is today's behaviour |
| `global` | one range for every map and the dots: `[lo, hi]` when both are given, else the finite `[min, max]` of the whole (C,H,W) array (`[0, 0]` if nothing is finite) |

- `lo`/`hi` are used only when `norm == "global"` and both are given. The compare view uses them for a shared scale.
- `peak` is now **always** the argmax `(py, px)` of the selected channel. Today it echoes the requested pixel.
  The inspected position stays in `vector.pixel` and `profile.row`, which are unchanged. Pixel clamping is unchanged.

Response additions for the `image` kind only (the sequence and vector kinds are unchanged):

```jsonc
{
  "norm": "channel",        // echo
  "cmap": "seq",            // echo
  "scale": null,            // [lo, hi] used when norm == "global", else null
  "maps": [{"channel": 3, "mean": 0.12, "map": [[...]], "range": [lo, hi]}],   // + range: the range that map was scaled with
  "dots_range": [lo, hi]    // the range `dots` was scaled with
}
```

With default arguments, `maps[*].map` and `dots` are identical to today's output.

**Preview**:

```python
def input_preview(x: np.ndarray, norm: tuple[Sequence[float], Sequence[float]] | None = None) -> np.ndarray | None
```

- Returns `None` unless `x.ndim == 4`, `x.shape[1] in (1, 3)` and `min(H, W) >= 8`.
- Takes sample 0 and returns `uint8`: (H, W, 3) for 3 channels, or (H, W) for 1 channel.
- When `norm = (mean, std)` is given, it computes `x*std + mean` per channel and clips to [0, 1].
- Otherwise it applies a per-channel min–max stretch.
- It does not resize; the caller does that.

**Diff**:

```python
def tensor_diff(a: np.ndarray, b: np.ndarray) -> dict
```

When the shapes differ, `diff` is `null`. Otherwise it contains these fields, all computed over positions where
both values are finite, in float64 (`# ponytail:` whole-array float64, chunk it if a run's tensors outgrow RAM):

| Field | Value |
|---|---|
| `stats` | `{mean, std, min, max}` of Δ = b − a |
| `hist` | `{counts[24], range}`, reusing `_hist` |
| `max_abs` | max \|Δ\| |
| `mean_abs` | mean \|Δ\| |
| `cosine` | cos(a, b), or `null` when either norm is 0 |
| `rel_l2` | ‖Δ‖ / ‖a‖, or `null` when ‖a‖ = 0 |

A field is `null` when there are no finite pairs.

### 1.2 `slicing.py` (new): safe NumPy-style slices

```python
SLICE_CAP = 4096          # values in one JSON table response
NPY_CAP = 1 << 24         # values in one .npy download (64 MB float32)

class SliceError(ValueError): ...          # bad syntax / out of range → HTTP 400
class SliceTooLarge(ValueError): ...       # beyond NPY_CAP → HTTP 413

def parse_slice(text: str, shape: Sequence[int]) -> tuple      # full-length key of ints and slices
def slice_table(arr, text: str) -> dict                          # JSON response below
def slice_npy(arr, text: str, cap: int | None = None) -> bytes   # cap defaults to module NPY_CAP read at call time
```

**Grammar.** Parsing uses regexes only. There is no `eval`, `ast` or `literal_eval`.

- `text` has at most 200 characters.
- Surrounding whitespace is allowed, and one optional pair of outer brackets `[ … ]`.
- Items are comma-separated. Each item is one of:
  - `...`
  - `-?\d+`, an index (negative counts from the end)
  - `(-?\d+)?:(-?\d+)?(:(-?\d+)?)?`, a start:stop:step slice
- Empty text, `[]` and `:` all mean "everything".
- An empty item such as `0,,1` is an error.
- `...` expands to `:` for every missing axis. Missing trailing axes are also `:`.

Errors are `SliceError`. Their messages are shown verbatim in the UI, so they must read well:

| Case | Message |
|---|---|
| unparsable item | `Cannot read "abc" (item 2). Use integers, start:stop:step, ":" or "...".` |
| two ellipses | `Only one "..." is allowed.` |
| more items than axes | `Too many indices: 5 for a 4-D tensor (1×64×56×56).` |
| index out of range | `Index 70 is out of range for axis 1 (size 64).` |
| zero step | `Slice step cannot be zero (axis 2).` |
| text too long | `Slice expression is too long (max 200 characters).` |

**Evaluation.** Basic indexing, `view = arr[key]`, is lazy on the memmap. The result is then truncated to
`SLICE_CAP` values:

- Go from the **last** axis backwards and keep `min(dim, max(1, cap // kept_so_far))` of each axis.
- For example, `(64, 56, 56)` becomes `(1, 56, 56)` and `(1, 197, 768)` becomes `(1, 5, 768)`.
- Then take `view[tuple(slice(0, k) for k in kept)]`, which is safe for any step sign.
- The index lists are `list(range(*s.indices(dim)))[:k]`.

`slice_table` response:

```jsonc
{
  "op": "conv2d_3_8",            // filled in by the route
  "expr": "[0, 12, 20:30, :]",   // as sent
  "key": "[0, 12, 20:30:1, 0:56:1]",   // canonical, fully expanded
  "shape": [10, 56],             // returned (after truncation); [] for a scalar
  "full_shape": [10, 56],        // shape of the whole slice
  "truncated": false,
  "axes": [2, 3],                // original axis of each returned axis
  "indices": [[20, 21, …, 29], [0, 1, …, 55]],   // original index along each returned axis
  "values": [0.1234, -0.5, "nan", …]            // flat, C order, len == prod(shape); floats to 6 significant digits, non-finite as "nan" | "inf" | "-inf"
}
```

`slice_npy`:
- It computes the slice's numel from the key without reading the data. Above the cap it raises
  `SliceTooLarge("Slice has 51,380,224 values; .npy export is capped at 16,777,216 (64 MB float32). Narrow the slice.")`.
- Otherwise it returns `np.save` bytes of `np.ascontiguousarray(arr[key], dtype=np.float32)`. The array keeps its full
  slice shape, with no truncation.

### 1.3 `models.py`, `runs.py`, `store.py`: input preview at capture

- `LoadedModel` gains `norm: tuple[tuple[float, ...], tuple[float, ...]] | None = None`, meaning (mean, std) per channel.
  It is set as follows:
  - `_load_torchvision`: `(IMAGENET_MEAN, IMAGENET_STD)`. With weights, use
    `(tuple(tf.mean), tuple(tf.std))` when the transform has those attributes, else ImageNet.
  - `_load_python`: ImageNet only when it falls back to `_default_image_preprocess`, else `None`.
- `store.py`: add `PREVIEW = "input_preview.png"` and list it in the layout docstring.
- `RunManager._create`: after `capture`, take `cpu = _to_device(inputs, "cpu")` and reuse it for `inputs.pt`. Then:
  - Take the first tensor of `cpu`. Pass `loaded.norm` only when `sample_meta["kind"] == "image"`, because random,
    tensor and in-process inputs are stretched instead.
  - Call `input_preview(...)`. If it returns an image, convert it with `PIL.Image.fromarray`, call
    `.thumbnail((224, 224))` and save it to `run_dir / PREVIEW`.
  - Set `meta["preview"] = {"width": w, "height": h}` from the saved image, or `None`.

### 1.4 HTTP API (`api.py`)

| Method | Path | Change |
|---|---|---|
| GET | `/api/runs/{id}/ops/{op}/tensor?channel=&py=&px=&norm=channel\|global&cmap=seq\|div&lo=&hi=` | new optional `norm` (`Literal`, default `channel`), `cmap` (`Literal`, default `seq`), `lo`/`hi` (float). Bad values give 422 |
| GET | `/api/runs/{id}/ops/{op}/slice?s=<expr>` | **new**. `slice_table` with `op` set. 400 `{detail: message}` on `SliceError`, 404 for an unknown run or op tensor |
| GET | `/api/runs/{id}/ops/{op}/slice.npy?s=<expr>` | **new**. `Response(bytes, media_type="application/octet-stream", headers={"Content-Disposition": 'attachment; filename="<safe_name(op)>.npy"'})`. 400 on `SliceError`, 413 on `SliceTooLarge`, 404 as above |
| GET | `/api/runs/{id}/diff?a=<op>&b=<op>` | **new**. `{"a", "b", "shape_a", "shape_b", "same_shape", "diff"}`, where `diff` comes from `tensor_diff` (null when the shapes differ). 404 when either tensor is missing |
| GET | `/api/runs/{id}/input.png` | **new**. `FileResponse(run_dir/PREVIEW, media_type="image/png")`. 404 when the run or the file is missing (old runs) |
| GET | `/api/runs/{id}` | meta now may carry `preview: {width, height} \| null` (absent on pre-M2 runs) |

Declare the `.npy` route and the `/slice` route separately; they are different paths. `s` defaults to `""`.

### 1.5 Backend tests (`backend/tests/test_tensor_m2.py`, new; `from test_pipeline import Tiny`; module-scoped `captured` fixture as in `test_graph_m1.py`)

1. **Norm.** Use a synthetic `(1, 3, 8, 8)` array whose channel *k* is `(k+1) * ramp`.
   - Default arguments: every map's max is 1, and `scale is None`. Each map's `range` is its own pooled range.
   - `norm="global"`: `scale == [min, max]` of the array, and only the channel holding the max reaches 1. Every
     `maps[i].range == scale`, and `dots_range == scale`.
   - `norm="global", lo=-10, hi=10`: `scale == [-10, 10]`.
2. **Diverging.** On a signed array, `cmap="div"` puts every value in `[-1, 1]`, gives an exact 0 wherever the pooled
   value is 0, and gives `max |v| == 1` in channel mode.
3. **Peak and pixel.** `tensor_view(arr, pixel=(0, 0))`: `vector.pixel == [0, 0]`, `profile.row == 0`, and `peak`
   is the argmax of the selected channel.
4. **`parse_slice` and `slice_table`**, on `np.arange(1*64*56*56).reshape(1,64,56,56)`:
   - `[0, 12, 20:30, :]` gives `shape == [10, 56]`, `axes == [2, 3]` and `indices[0] == list(range(20, 30))`, and
     the values equal `arr[0, 12, 20:30, :].ravel()`.
   - `...` works: `[..., 0]` gives `full_shape == [1, 64, 56]`.
   - `[-1]`, `::-2` and whitespace variants work.
   - `[0]` truncates: `shape == [1, 56, 56]`, `full_shape == [64, 56, 56]`, `truncated` is true, and there are at
     most 4096 values.
   - Each of these raises `SliceError` with the message from §1.2: `[0,0,0,0,0]`, `[0, 99]`, `[1:2:0]`, `[a]`,
     `[..., ...]`, `__import__('os')` and a 201-character string.
   - An array containing NaN/Inf returns `"nan"`/`"inf"` strings.
5. **`slice_npy`.** `np.load(BytesIO(slice_npy(arr, "[0, 1:3]")))` equals `arr[0, 1:3]` as float32. With a small
   cap (`slice_npy(arr, "", cap=10)`) it raises `SliceTooLarge`.
6. **`tensor_diff`.**
   - A tensor against itself: `max_abs == 0` and `cosine == 1`.
   - `relu(x)` against `x`: `max_abs == max(-x.min(), 0)` within tolerance.
   - Different shapes: `diff is None`.
7. **`input_preview`.**
   - With `norm=(mean, std)`, `((p - mean)/std)` round-trips to `round(p*255)` within ±1.
   - A `(1, 10)` input gives `None`.
   - A 1-channel input gives `ndim == 2`.
8. **HTTP.**
   - The tensor endpoint accepts `norm=global&cmap=div` and echoes both; `norm=bad` gives 422.
   - `/slice?s=[0,0]` gives 200. `/slice?s=[0,99]` gives 400 and the detail mentions `axis 1`.
   - `/slice.npy` gives 200 with `application/octet-stream`, and `np.load` works on the body. With
     `monkeypatch.setattr(neurotome.slicing, "NPY_CAP", 10)` it gives 413.
   - `/diff?a=<relu op>&b=<its parent>` gives 200 with `same_shape` true. An unknown op gives 404.
   - Tiny's run meta has `preview == {"width": 16, "height": 16}`, and `/input.png` gives 200 `image/png` that PIL
     opens. After deleting the file, it gives 404.
   - A run with a `(1, 10)` input (a small `nn.Linear` model) has `preview is None`.

Checks: `cd backend && ../.venv/Scripts/python.exe -m pytest -q && ../.venv/Scripts/python.exe -m ruff check .`

## 3. Item 1: click a pixel (packages B and C)

**Behaviour** (C, `TensorView.tsx`):
- URL: `#/runs/<id>/tensors?node=…&c=…&py=…&px=…`. `py`/`px` are sent only as a pair (`api.tensor` opts).
- Clicking a dot-matrix cell sets the pixel to that cell's centre pixel. In the channel grid:
  - clicking the **selected** channel's tile sets the pixel in the same way (with the tile's grid size);
  - clicking any other tile selects that channel and keeps `py`/`px`, because the position is spatial.
- Changing the node clears `c`, `py`, `px` and `cmp`. Changing the channel keeps `py`/`px`.
- The left rail gets a `Position` row, under the channel input:
  - two `.field` number inputs (y 0–H−1, x 0–W−1) showing `vector.pixel`;
  - a `Peak` text button that clears `py`/`px`, so the server falls back to the argmax.

  This is also the keyboard path.
- Crosshair: `mark = [cellOf(H, rows, py), cellOf(W, cols, px)]` on the DotMatrix, on the selected tile of the
  grid and on the overlay. `LinePlot` (profile) gets `mark = cellOf(W, profile.values.length, px)`.
- The channel vector head reads `Channel vector @ (py, px)`, and the profile head `Row py profile`. Both come from
  the response. The right-panel stats show `Peak (y,x)` (argmax) and `Pixel (y,x)`.
- The dot readout reads `px (y0–y1, x0–x1) · <value>`. The value is `unscale(v, dots_range, cmap)`, so it is real
  and not normalised.

**Pure logic** (C, `lib/tensorState.ts`; mirrors `np.array_split` as used by `_pool1d`):

```ts
cellStart(len: number, n: number, i: number): number   // q = ⌊len/n⌋, r = len % n → i·q + min(i, r)
cellOf(len: number, n: number, p: number): number      // inverse: the cell containing pixel p (p clamped)
cellPixel(len: number, n: number, i: number): number   // centre pixel ⌊(start(i) + start(i+1) − 1) / 2⌋
unscale(v: number, range: [number, number], cmap: Cmap): number   // seq: lo + v(hi−lo); div: v·max(|lo|,|hi|)
```

`n` is always the rendered grid length, `min(len, pool size)`. When `n == len` all three functions are the identity.

**Tests** (`lib/tensorState.test.ts`):
- For `(56, 16)`, `cellStart` gives 0, 4, …, 28, 32, 35, …, matching NumPy's split sizes of eight 4s then eight 3s.
- `cellOf(56, 16, 33) == 8`, and `cellOf(cellPixel(i)) == i` for every i.
- The identity holds for `(7, 7)`.
- `unscale` round-trips for both colormaps.

## 4. Item 2: normalization and colormap (A computes, B draws, C wires)

- URL: `norm=global` (default `channel`, omitted) and `cmap=div` (default `seq`, omitted). Both are kept when the
  node or channel changes. They apply to the image kind only; the controls are hidden for sequence and vector views.
- The left rail gets two `.seg`s under Position:

## 9. Item 7: ModuleTree selects the module (B)

The bug: `ModuleTree.onPick(addr)` → `pickNodeForModule`. When the module is open (a group), that returns the

- `GraphView` loads the index once (`useAsync(() => api.index(run.id), [run.id])`) and passes it to `GraphSearch`.

- Tree pick:
  1. If a visible node has `path === addr` (a folded module or a single-op module), select it and increment
     `centre`. There is no fold change.
  2. Else, when `moduleEntry(entries, addr)` exists, call the same `onPick(entry)` as search. That is
     `revealFold` + select + centre, which folds an open module into its node `m:<call>` and reveals one hidden
     inside a collapsed ancestor.

- **Pure** (`lib/graphState.ts`): `moduleEntry(entries: IndexEntry[], address: string): IndexEntry | null`. It
  returns the first `kind === "module"` entry with `path === address`, else the first entry with that path, else `null`.
